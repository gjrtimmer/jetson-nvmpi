# create-release (jetson-nvmpi)

Create a libnvmpi release end-to-end. Invoke: **`/create-release [vX.Y.Z]`**.

Ported from the jetson-ffmpeg skill. Differences that matter here:

- GitLab project: `timmertech/jetson-nvmpi` (API path `timmertech%2Fjetson-nvmpi`).
- Releases: the tag pipeline creates the GitLab release (`release:gitlab`) and
  the GitHub release (`release:github`, via API once the push-mirror delivers
  the tag). Never create a GitHub release by hand, never push to GitHub.
- The tag pipeline **fails** unless `project(nvmpi VERSION X.Y.Z ...)` in
  `CMakeLists.txt` equals the tag (`dist` job gate). Version bump is mandatory.
- Tags `v2.0.0`..`v3.10.0` are jetson-ffmpeg releases from before the split.
  `CHANGELOG.md` only covers `v3.10.0..HEAD`; never regenerate it over the
  full history.

## Files every release touches

| File | Change |
|------|--------|
| `CMakeLists.txt` | `project(nvmpi VERSION X.Y.Z ...)` (skip if already equal) |
| `CHANGELOG.md` | Regenerated by git-cliff with the new version heading |

Nothing else carries the release version. `CPACK_*_REPLACES/BREAKS "libnvmpi (<< 4.0.0)"`
and doc examples (`3.10.0`, `4.0.0-1~jp6`) are fixed references, not the
current version: leave them.

## Subagents

- Default **haiku** for grunt work (pipeline status, git log, `glab` calls).
- **sonnet** for investigating a failed pipeline.
- Always pass `model:` explicitly.

## Phase 0: Determine version

| Argument | Behavior |
|----------|----------|
| `vX.Y.Z` | Use as given; must be > latest tag |
| `patch` / `minor` / `major` | Bump that component of the latest tag |
| _(none)_ | Auto-detect from commits since latest tag |

Auto-detection:

```bash
LAST=$(git describe --tags --abbrev=0 origin/main)
git log --no-merges --format='%s%n%b' "$LAST"..origin/main
```

- `type!:` or `BREAKING CHANGE:` footer → major
- any `feat` → minor
- otherwise → patch

Then take `max(detected, CMake VERSION)`: if `CMakeLists.txt` was already
bumped ahead by a commit (e.g. `bump to 4.0.0`), that version wins. Confirm
with the user if connected:

```
Latest tag: v3.10.0   CMake VERSION: 4.0.0
Commits since tag: 0 feat, 2 fix, 1 build
Detected: patch → v3.10.1, CMake ahead → v4.0.0
Proceed? [Y/n]
```

Output: `VERSION_TAG=vX.Y.Z`, `VERSION=X.Y.Z`.

## Phase 1: Pre-flight (no mutations)

```bash
glab auth status
git branch --show-current          # switch to main if not on it
git status --porcelain             # must be empty
git fetch --tags origin && git pull --ff-only origin main
git tag -l "$VERSION_TAG"          # must be empty
sed -n 's/^project(nvmpi VERSION \([0-9.]*\).*/\1/p' CMakeLists.txt
command -v git-cliff               # missing: brew install git-cliff
glab mr list --target-branch main
glab api 'projects/timmertech%2Fjetson-nvmpi/pipelines?ref=main&per_page=1' | jq '.[0] | {id,status,sha}'
```

| Check | Pass | Fail |
|-------|------|------|
| glab auth | authenticated | STOP, ask user to `glab auth login` |
| working tree | clean | STOP, ask user to commit their changes |
| tag free | `git tag -l` empty | STOP, ask if retraction intended |
| version | `VERSION` > latest tag and >= CMake VERSION | STOP, downgrade |
| git-cliff | present | install, or STOP |

Open MRs targeting main are release-blocking: go to Phase 2. Latest main
pipeline not `success`: go to Phase 2. Otherwise skip to Phase 3.

---

## Phase 2: Wait for MRs and pipelines

- Poll with `ScheduleWakeup` at **600s** (pipeline polling rule).
- MR merged → re-check main pipeline of the merge commit.
- MR pipeline failed → STOP, report, do not release.
- Main pipeline `failed` → STOP, diagnose (sonnet subagent), do not release.
- Continue only when no open MRs remain and latest main pipeline is `success`;
  then `git pull --ff-only origin main`.

---

## Phase 3: Validate scope

```bash
git log --oneline --no-merges "$LAST"..origin/main
```

Show the list. Every intended issue/MR must be in it.

---

## Phase 4: Bump and regenerate

4a. CMake (only when it differs):

```bash
sed -i '' "s/^project(nvmpi VERSION [0-9.]*/project(nvmpi VERSION ${VERSION}/" CMakeLists.txt
```

(GNU sed on Linux: `sed -i` without `''`.)

4b. CHANGELOG — always the fixed post-split range, full regenerate (idempotent):

```bash
git-cliff --config cliff.toml --tag "$VERSION_TAG" v3.10.0..HEAD -o CHANGELOG.md
```

Never drop the `v3.10.0..HEAD` range: without it git-cliff pulls in every
jetson-ffmpeg release since v2.0.0.

4c. Check: `git diff CMakeLists.txt CHANGELOG.md`. Top section must be
`## X.Y.Z - <today>`, no `## Unreleased` left. The CI job
(`scripts/changelog.sh`, `--latest --strip header`) builds the GitLab release
notes from the same `cliff.toml`, so they match this section.

---

## Phase 5: Commit, tag, push

Confirm with the user before pushing (outward-facing) unless they already said
to release unattended.

```bash
git add CMakeLists.txt CHANGELOG.md
git commit -m "docs: update CHANGELOG for ${VERSION_TAG} release"
git push origin main -o ci.skip
git tag -a "$VERSION_TAG" -m "$VERSION_TAG"
git push origin "$VERSION_TAG"
```

- If CMake was bumped in this commit, use `chore(release): ${VERSION_TAG}`
  instead (not docs-only).
- No `[ci skip]`/`[skip ci]` in messages; no attribution trailers.
- `-o ci.skip` on main only: the tag pipeline is the one that matters.

---

## Phase 6: Monitor the tag pipeline

```bash
glab api "projects/timmertech%2Fjetson-nvmpi/pipelines?ref=${VERSION_TAG}&per_page=1" | jq '.[0] | {id,status}'
```

Stages: build → test (`test:api:jp6` on Jetson) → dist (real build + `.tar.gz`
+ `.deb`, tag/CMake gate) → publish (`upload:s3`, changelog) → release
(`release:gitlab` and `release:github`, independent).
Poll every **600s**.

- `success` → Phase 7.
- `failed` → abort (below), then diagnose.

---

## Phase 7: Verify

```bash
glab api "projects/timmertech%2Fjetson-nvmpi/releases/${VERSION_TAG}" | jq '{name, tag_name, assets: (.assets.links | length)}'
gh release view "${VERSION_TAG}" -R gjrtimmer/jetson-nvmpi --json name,assets --jq '{name, assets: (.assets | length)}'
```

- [ ] GitLab release `vX.Y.Z` exists, asset links for tarballs + debs (jp5, jp6) + `CHANGELOG.md`
- [ ] GitHub release `vX.Y.Z` exists (created by CI, never by hand) with 6 package
      assets (2 tarballs + 4 debs) + `CHANGELOG.md` = 7 total
- [ ] Release notes match the top section of `CHANGELOG.md`
- [ ] `trigger:jetson-ffmpeg` is manual: mention it, do not run it unless asked

Report final status: commit SHA, tag, pipeline id, release URL.

---

## Abort procedure

After the tag is pushed and something fails:

1. Cancel pipeline: `glab api --method POST "projects/timmertech%2Fjetson-nvmpi/pipelines/<ID>/cancel"`
2. Delete GitLab release (if created): `glab api --method DELETE "projects/timmertech%2Fjetson-nvmpi/releases/${VERSION_TAG}"`
3. Delete tag: `git push origin ":refs/tags/${VERSION_TAG}" && git tag -d "$VERSION_TAG"`

The push-mirror removes the tag from GitHub. The release commit on main
stays; fix the cause, re-run the skill (the CHANGELOG regenerate is idempotent).
